# 프론트엔드 디자인 점검·다듬기 설계

- 작성일: 2026-09-10
- 상태: 사용자 승인 대기
- 관련 스킬: `frontend-design:frontend-design`(Anthropic), `impeccable`(pbakaus, v4.3.1)

## 1. 목적

□ 현재 배포 중인 밀어요 앱 UI 를 두 디자인 스킬의 기준으로 점검하고, 결과 보고서를 남긴 뒤 합의된 항목을 수정하여 배포
□ 방향: 현재 정체성(Pretendard 서체, 녹색 강조색, 흰 카드 구성) 유지. 재설계 아님
□ 두 스킬의 역할 분담
  - impeccable: 점검 절차와 채점 틀(audit 5항목, critique 휴리스틱 10항목, 안티패턴 검출기), 수정 원칙(polish)
  - frontend-design: 디자인 특이성 판정 기준(AI 기본값 패턴 회피, 한 곳에만 과감함, 절제)과 문구 원칙

## 2. 점검 대상

□ 화면 3개
  - 홈 `#list`: 로고·다운로드, GPS 버튼·후보, 번호 표시·키패드, 일치 칩, 구역 탭·칩
  - 주기장 상세 `#detail`: 내비바, 정보 카드, 절차 카드, 주의사항, 도면·애니메이션, 경로이탈 경보
  - 도면 라이트박스 `.lightbox`
□ 제외: 이용집계 화면(관리자 전용, `#verTap` 5회 연타 진입)
□ 테마: 라이트·다크 모두
□ 뷰포트: 390×844 (현장 휴대폰 기준). 보조로 360×780 확인
□ 모드: impeccable 의 Operate 모드. 스캔 가능성·일관성·표준 관행이 표현보다 우선

## 3. 점검 기준

□ audit (impeccable, 각 0~4점, 20점 만점)
  - 접근성, 성능, 테마, 반응형, 구현 일관성
□ critique (impeccable, Nielsen 휴리스틱 10개 각 0~4점, 40점 만점)
  - 인지 부하 체크리스트, 감정 여정, 페르소나 적신호 포함
□ 디자인 특이성 (frontend-design)
  - 이 제품이 아니어도 그대로 쓸 수 있는 구성인지 판정
  - AI 기본값 패턴 점검: 동일 radius 의 카드 나열, 동일 회색 그림자, ALL-CAPS 눈썹 라벨, 중점(·)으로 이은 메타 문자열, 장식용 모션
  - 문구: 능동태, 동작 이름 일관성, 오류·빈 화면은 방향 제시
□ 현장 조건 가중치 (사용자 지정)
  - 장갑·한 손 조작: 터치 목표 48×48px 이상, 엄지 도달 범위 내 주요 버튼
  - 야간·어두운 환경: 다크모드 완성도, 경보 배너 야간 가독성
  - 야외 주간 직사광: 본문 대비 7:1 목표(AAA), 작은 회색 보조 글자 최소화
□ 안전 문구 보호: "작업자 단말 위치이며 항공기 위치가 아닙니다", "(시범)" 표기 등 사실 고지 문구는 점검 대상이되 삭제·완화 불가

## 4. 점검 절차

□ 사전 준비
  - `/plugin install impeccable@impeccable` (사용자 실행)
  - `impeccable context` 1회 실행
  - PRODUCT.md 부재 → `impeccable init` 으로 제품 맥락 기록 (현장 작업자, Operate 모드, 오프라인 PWA, 안전 문구 제약)
  - `serve.ps1 -NoBrowser` 로 로컬 서빙, 헤드리스 Edge 로 스크린샷 6장 촬영 (3화면×2테마). 상세 화면은 `#gate=번호` 해시로 진입
□ audit: 코드 수준 점검. 주 작업자가 직접 수행
  - 대비 계산 node 스크립트 (CSS 변수 조합별 전경/배경 대비)
  - 터치 목표 측정 (헤드리스 Edge 에서 getBoundingClientRect)
  - 하드코딩 색 목록 (JS 인라인 스타일 포함), 다크모드 누락 항목
  - 애니메이션·will-change·이미지 로딩 점검
□ critique: 하위 에이전트 2개 병렬, 서로 결과를 보지 못함
  - A 디자인 리뷰: 스크린샷 6장 + CSS/HTML 원본. 프롬프트에 3절 기준 전체(frontend-design 원칙, 현장 조건, 안전 문구 보호) 포함. 휴리스틱 채점, 강점 2~3, 우선 이슈 3~5, 페르소나 적신호 반환
  - B 검출기·브라우저 증거: `impeccable detect --json index.html` 실행, 브라우저 주입 가능 시 오버레이 결과 수집. 오탐 후보 표시
  - 종합: A 완료 후 B 결과를 합침. 일치·불일치·오탐을 구분
□ 결과가 동작 변경을 요구하는 항목(예: 뒤로가기 처리)은 발견 사항으로만 기록

## 6. 수정 단계

□ 브랜치: `feature/frontend-polish`. main 직접 커밋 없음
□ 원칙 (impeccable polish)
  - 팔레트·서체·radius·카드 구조 유지
  - 원인을 가장 좁은 수준에서 수정: 토큰 누락 → 토큰 추가, 일회성 구현 → 기존 패턴으로 교체, 국소 결함 → 그 자리 수정
  - 사실 문구·안전 문구는 변경 전 사용자 확인
□ 배포 2회 분할
  - 1차: 시각 변화 없는 수정. 접근성 속성, 포커스 처리, 다크모드 누락 값, 터치 목표 확대, 하드코딩 색의 토큰화
  - 2차: 눈에 보이는 변화. 레이아웃 간격, 위계, 문구, 상태 표시
  - 각 차수마다 배포 체크리스트 수행: `C_VER` 과 `sw.js` 캐시명 동시 증가, 헤드리스 Edge 콘솔 오류 없음, 변경 파일 범위 확인, 사용자 보고 후 `git merge --no-ff` 와 `(vNNN)` 표기
□ 수정 후 audit 재채점. 전후 점수와 스크린샷 비교를 보고서에 추가

## 7. 범위 밖 (기록만, 이번 작업에서 수정하지 않음)

□ `gcFlush()` 함수의 닫는 괄호 누락으로 이후 함수들이 중첩된 상태 (index.html 3955행 부근). `#verTap` 5회 연타 등록이 online 이벤트 이후에야 이루어짐
□ 라이트박스 `bindZoom` 의 `apply()` 안 항상 0 이 되는 계산 (3435행 부근)
□ 안드로이드 뒤로가기 버튼으로 목록 복귀가 안 되는 동작 (`history.replaceState` 만 사용)
□ 이용집계 화면 UI
